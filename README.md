# Flutter Base Project

Starter project with the same architecture as the MashLife app:
**Cubit (flutter_bloc) + GetIt + Dio + Hive + FlutterGen + JSON localization.**

It has only one sample feature (Sign In and Home) to show the pattern.
Copy this project, rename it, and start adding your features.

## Setup

```bash
flutter pub get
dart run build_runner build      # generates lib/gen (colors, assets, fonts)
flutter run --dart-define=ENV=stage
```

Environment is picked with `--dart-define=ENV=local|stage|live` (default is `stage`).
Base URLs are in `lib/data/api/api_constants.dart`.

## How to add a new feature

Example: a "Profile" screen.

1. **End point** in `api_constants.dart`:
   `static const String profile = '${_prefix}profile';`
2. **Model** in `features/profile/model/profile_model.dart` with `fromJson` / `toJson`.
3. **Repo** in `features/profile/repo/profile_repo.dart`:
   ```dart
   class ProfileRepo extends ApiCaller {
     Future<BaseResponse> getProfile() =>
         execute(() => apiService.get(url: ApiConstants.profile));
   }
   ```
4. **Cubit** in `features/profile/cubit/profile_cubit.dart`:
   ```dart
   class ProfileCubit extends BaseCubit {
     ProfileCubit({ProfileRepo? repo}) : _repo = repo ?? ProfileRepo();
     final ProfileRepo _repo;

     Future<void> getProfile() async {
       emit(Loading());
       final res = await _repo.getProfile();
       if (res.isSuccess) {
         safeEmit(ApiSuccess(ProfileModel.fromJson(res.data)));
       } else {
         onApiError(res.displayMessage);
       }
     }
   }
   ```
   If the feature needs its own states, put them in `features/profile/state/profile_state.dart`
   and extend `ApiRenderState`.
5. **Screen** `features/profile/profile_screen.dart` extends `BaseWidget`, uses
   `BlocProvider` + `BlocBuilder<ProfileCubit, ApiRenderState>` and `StackLoader`.
6. **Route**: add a name in `Routes` and a `case` in `onGenerateRoute`, then
   `navigation.push(Routes.profileScreen)`.
7. **Text**: add keys in `assets/languages/en.json` and a line in `string/string.dart`.
8. **New colors or images**: add to `colors.xml` or `assets/drawables/`, then run
   `dart run build_runner build`.

## Rules followed in this structure

- Screens do not call APIs. Screen -> Cubit -> Repo -> ApiCaller -> ApiService.
- Repos always return `BaseResponse` (never throw). Check `res.isSuccess`.
- Use `safeEmit()` after `await` so a closed cubit does not crash.
- Use `CommonDi` getters (`navigation`, `storage`, `toast`, `misc`, `dateTime`, `eventBus`)
  instead of calling `GetIt` in many places.
- Toasts do not need context: `showError(msg)` / `showSuccess(msg)`.
- 401 response logs the user out and opens the Sign In screen automatically.
- Losing internet opens `NetworkIssueScreen`, it closes by itself when internet is back.

## Not included (add per project)

Firebase (push, analytics), Sentry, Stripe, Google Maps, social login, image picker,
permission handler, deep links. The MashLife project has working examples in
`lib/presentation/service/` if you need them.
